# 미실행 감소를 위한 변경과 검증

이 문서는 최종 코호트의 집계 전에 확정한 변경 내역이다. 현재 실행 상태는 [STATUS.md](STATUS.md), 기존 46개 행의 원본 대응은 [not-run-baseline.json](not-run-baseline.json), 확대 직전 검증은 [smoke-r4-summary.md](smoke-r4-summary.md)에 있다.

## 무엇을 줄이는가

`ee4b145`의 미실행 46개는 고유 15명의 완료 24세션에 포함된 **성공 기준의 반복 관측 46행**이다. 중복을 제거하면 페르소나–요구사항 조합은 32개다. 최종 보고서는 각 기존 행을 새 코호트의 같은 페르소나·요구사항·기준 종류에 대응시킨다. 새 판정이 통과 또는 실패일 때만 실제 평가 범위가 늘어난 것으로 센다. N/A·미평가는 감소 성과에 넣지 않는다.

| --- | ---: | --- |

## 실행기·fixture·과제 변경

- **진행 중 취소:** 51~104ms에 끝나던 fixture를 대체하는 유효한 대용량 fixture를 만들었다. v7 ZIP은 57,961,041 bytes이며 인식 JSON은 57,960,093 bytes로 제품의 64MiB 합계 제한 안이다. 실제 reading/analysis 상태에서 취소를 한 번 전송하고 저장 전후 digest를 비교한다. 크기 제한에 먼저 걸렸던 v6는 보존하고 사용하지 않는다.
- **클릭과 스크롤:** 현재 관측에서 보이는 활성 대상인지, 모달 소유권과 hit test가 맞는지 다시 확인한다. 고정 좌표 휠 대신 활성 모달의 실제 스크롤 영역을 사용하고 전후 이동량·배경 이동을 기록한다. 조작 후 움직이지 않았다는 이유로 자동 재전송하지 않는다.
- **과제 의존성:** sample export를 먼저 수행하고, retention과 paywall을 함께 맡은 경우 11개 기록을 먼저 만든다. PAYWALL만 맡아도 이전 기록 하나를 준비한 뒤 비교 pair를 만든다. 목록·날짜 선택기·Pro 설명을 각각 확인하며, 같은 모달을 다시 여는 행동으로 탐색 한도를 초기화하지 않는다.
- **장시간 과제:** 최대 64턴과 턴 수에 맞는 체크포인트 저장 한도를 사용한다. 모델에는 오래된 관측을 압축해 전달하지만 최신 조작 대상과 원본 저장 증거는 유지한다. 기존 1MiB 체크포인트 한도로 중단된 smoke는 재개하지 않았다.
- **판정 연결:** 실제 비교 화면에서 안내를 확인하고, 저장 실패·크기 제한·취소 증거를 같은 upload attempt의 fixture·상태에 연결한다. 저장 실패 통과에는 실제 재시도와 새 결과 저장이 필요하다. native 실패의 제한된 reason을 admission schema가 정상 수용하도록 고쳤다.
- **불확실 전송 차단:** 각 call ID의 dispatch intent와 reply/uncertain 상태를 영구 기록한다. 전송 후 타임아웃·전달 불명확 오류는 재시도·fallback 없이 불확실로 보존한다. 이미 완료된 응답의 형식·품질 복구와 전달 불확실 재전송은 원장에서 구분한다.

런타임은 `43e3b143cdfee0a8ae23f68808ebf850e99008bb`, 최종 fixture manifest는 `4df650d58c2105bc67ca3eec27c826b1f8129f8f1a846b396a4eb9e53c48f44a`로 동결했다. 기존 원본 fixture·큐·저장 페르소나를 덮어쓰지 않았다.

## 기준을 보존한 범위와 해석

`ee4b145 → 43e3b14`에서 PRD 기준 25개의 ID, 화면, selector, 필수 텍스트, 기대값, 기준별 제한시간과 검증 범위는 동일하다. 관측 연결과 판정 정확도를 고쳤으므로 판정 로직까지 완전히 같은 실험은 아니다. 결과 차이에는 실행 범위 확대와 판정 오류 수정이 함께 반영된다.

제품은 `51110f4`로 고정했고 제품 소스를 수정하지 않았다. 더 명시적인 과제와 합성 fixture, 늘어난 턴 예산의 결과이므로 자연스러운 첫 사용 성공률이나 사용 시간의 개선으로 해석하지 않는다.

## 초기 스모크의 재전송 사고

**첫 스모크에서 기존 라우터의 내부 타임아웃 재전송 5건(4개 call ID)이 발견됐다.** 해당 실행은 중단·보존했으며 확대 근거로 사용하지 않았다. 사용자에게 알리고 영구 delivery guard와 회귀를 추가했다. 따라서 이 작업 전체가 처음부터 재전송 0이었다고 보고하지 않는다.

수정 후 r2·r3·r4 원장에서는 불확실 재전송 0을 확인했다. 최종 32명 원장 감사는 코호트 종료 후 별도 수행한다. 각 스모크 원본과 진단은 [r1](smoke-r1-diagnostics.md), [r2](smoke-r2-diagnostics.md), [r3](smoke-r3-diagnostics.md), [r4](smoke-r4-summary.md)에 보존했다.
