# Peekly 실제 모델 여정 — 증거 해석과 UX 검토

이 문서는 보존된 큐·원장·관측 로그·PNG 해시와 고정된 제품 소스를 대조한 검토다.
새로 실제 사용자를 모집한 조사도, 독립적인 사람 평가자의 투표도 아니다.
동일 페르소나 모델의 자체 재검토와 이 읽기 전용 증거 감사는 서로 다른 범위로 표시한다.

## 완료의 의미를 바로잡기

이전 `stage4-final` 큐의 `complete=4`를 여정 성공 4건으로 읽으면 안 된다.
그 실행의 `operational_completed`는 모두 false였고, 세 세션은 `turn_limit`,
한 세션은 `judgment_invalid`로 닫혔다. 실제 화면·업로드 관측은 일부 있었지만
유효한 최종 판정까지 완료된 세션은 없었다. 기존 원장과 실패 이력은 수정하지 않았다.

수정된 `peekly-verified-20261113-r3/stage-4`는 별도 새 실행이다. 네 세션이 모두
최종 판정·동일 페르소나 재검토·브라우저 종료를 완료했고, 39개 PNG와 39개 관측 로그가
재검증됐다. 전체 UX 판정은 네 건 모두 inconclusive다. 공유·복구 등 실행하지 않은
요구사항이 남아 있으므로, 유효한 최종 판정은 제품 전체 통과를 뜻하지 않는다.

## UX-01 — 수동 재가져오기 발견성

**관측:** 결과 화면에서 직접 파일을 넣는 항목은 `연결 관리와 다른 방법` disclosure
안의 `이미 받은 자료로 확인하기`다. 이 컨트롤이 첫 관측에서 화면 밖으로 표시된
여정이 있으며, 일부 페르소나는 `더보기`에서 가져오기를 찾지 못하고 결과로 돌아왔다.
현재 빌드의 `ResultsTab.tsx` 282–297행도 이 구조와 일치한다.

**별도로 확인한 코드 연결:** 결과 화면의 `새로 확인하기`는 직접 파일 선택이 아니라
`App.tsx` 1388행의 `handleConnectInstagram()`에 연결된다. 직접 가져오기는
1386행의 별도 `onImportNewBackup` 콜백이다. 이는 코드 연결 확인이며, 실제 인스타
로그인이나 계정 연결을 실행했다는 뜻이 아니다.

**개선 후보:** 수동으로 백업을 가져온 이용자에게는 결과 화면에서 `새 백업 불러오기`를
바로 찾을 수 있게 하고, 계정 연결을 사용하는 새로고침과 의미를 구분한다. 기존 로그인
우선 제품 방향을 없애는 제안은 아니다. 두 경로가 다른 행동임을 UI에서 드러내자는 제안이다.

**한계:** 모델은 DOM 컨트롤 메타데이터와 일부 명시적 과업 안내를 받았고, 드라이버가
자동 스크롤을 보조했다. 따라서 이 기록으로 사람의 발견율이나 평균 소요 시간을 추정할 수 없다.

## UX-02 — 이미 받은 파일인데 파일 요청 안내부터 다시 시작

**관측:** `이미 받은 자료로 확인하기`를 눌러도 `인스타그램에 내 파일을 요청해요`라는
1/3단계가 먼저 열리고, 이후 `받은 파일 바로 넣기`를 다시 선택해야 3/3 업로드 단계로
이동한다. 해당 화면과 파일 입력 단계는 각각의 실제 관측 로그에 남아 있다.

**개선 후보:** 이미 파일을 갖고 있다는 선택에서 진입했다면 곧바로 파일 넣기 단계로
이동하고, 파일을 다시 요청해야 하는 경우에만 요청 안내를 펼치게 한다.

## UX-03 — 단일 백업 이후의 다음 행동 설명

**관측:** 제공된 current ZIP을 넣은 뒤 `결과를 불러왔어요`와 팔로워 7명·팔로잉 10명,
관계 범주 5명·2명·5명이 표시되는 흐름을 확인했다. 샘플 표시가 사라지고 결과의 다음
행동으로 알림·새로 확인하기·계정 연결 안내가 보였다. 이 숫자는 고정 합성 ZIP의 값이다.

**개선 후보:** 계정 연결 여부와 별개로, 다음 시점의 백업을 가져오면 기록을 비교한다는
수동 경로도 명확히 설명한다. 단일 스냅샷만으로 과거 언팔로우를 확정한 것처럼 안내하지 않는다.

## 실행기 문제와 제품 문제의 구분

일부 기록에는 가져오기 버튼을 요청했는데 계정 상세 시트가 열린 뒤 닫고 재시도한
관측이 있다. 이는 DOM/좌표/스크롤 안정성과 제품 레이아웃을 함께 재현해야 하는 현상이다.
기록만으로 제품 클릭 핸들러의 결함이라고 확정하지 않는다. PNG는 증거로 저장되지만
현재 모델 경로에는 이미지 픽셀이 전달되지 않는다.

## 모델 판정의 의미 한계

첫 페르소나의 최종 판정에는 ‘로컬 처리 문구와 외부 차단을 보았지만 공유 이미지 경로는
실행하지 않았다’면서 복합 개인정보 요구사항을 passed로 둔 항목이 있다. 이는 모델의
개별 요구사항 과잉 판정 가능성으로 남긴다. 원래 모델 판정을 사후에 바꾸지 않으며,
공유 이미지나 서버 부재를 검증했다고 보고하지 않는다. 호스트의 네트워크 차단은 제품의
프로덕션 개인정보 보호를 입증하지 않는다.

이번 여정은 정상 합성 ZIP을 사용했다. HTML 오류, 누락·다른 계정 파일, 128MB 경계,
저장 실패, 실제 iOS 접근성·공유·OAuth, 실제 사용자 효과는 별도 검증이 필요하다.
관측 뷰포트 756×413을 iPhone 실기기 검증이라고 표현하지 않는다.
