# 한국어 보고서 틀

한국어로 쓰는 리서치 보고서의 뼈대와 문체 규칙입니다. 내용은 영문 틀 `references/research/output-template.md`와
같고, 한국어 문체와 표시 규칙을 더합니다. 등급과 주장 상태는 `references/research/source-grading.md`를, 접근 표와
중단 유형은 `references/research/public-page-access.md` 5절, 6절, 15절을 따릅니다. 한국 리서치 팩의 흐름은
`references/research/korea/overview.md`에서 시작합니다.

1절 "작성 규칙"은 보고서에 옮기지 않습니다. 2절의 뼈대를 복사해 채웁니다.

## 1. 작성 규칙(보고서에 옮기지 않음)

### 1.1 문체

- 본문은 합니다체로 통일함. 표와 근거 줄은 개조식(~함, ~임)으로 씀.
- 짧고 쉬운 문장을 씀. 한 문장에는 사실 하나를 담음.
- 한 개념에는 한 단어를 씀(1.6절).
- 확신의 정도는 상태 표시(1.2절)와 주장 상태(1.3절)로 나타내고, "분명히", "확실히" 같은 말로 부풀리지 않음.
- 파일 이름, 코드 이름, 상태 코드는 원래 표기(ASCII)대로 둠.

### 1.2 상태 표시

문장과 근거 줄에는 아래 세 표시 가운데 하나를 붙입니다.

| 표시 | 뜻 | 함께 적는 것 |
| --- | --- | --- |
| 관찰됨 | 읽은 출처에 직접 있는 내용 | 출처 ID |
| 추론 | 관찰에서 끌어낸 판단 | 바탕이 된 주장 ID나 출처 ID, 짧은 이유 |
| 미확인 | 확인하지 못한 내용, 단서뿐인 내용, 읽지 못한 출처에 기댄 내용 | 무엇을 확인해야 하는지 |

표시는 문장의 성격이고, 주장 상태(1.3절)는 주장의 근거 수준입니다. 둘을 함께 씁니다.

### 1.3 주장 상태 풀이

상태 코드는 영문 그대로 두고 한국어 풀이를 붙입니다. 상태는 `gate`(계획)가 계산합니다. `gate`가 나오기 전에는
`references/research/source-grading.md`를 손으로 적용하고, 표 옆에 "손으로 등급 매김(gate 아님)"이라고 적습니다.

| 코드 | 풀이 | 보고서에서 둘 곳 |
| --- | --- | --- |
| `supported_high` | 근거 충분(높음) | 본문 |
| `supported_medium` | 근거 충분(보통) | 본문 |
| `single_voice` | 한 사람의 보고 | 부록만 |
| `lead_only` | 단서만 있음 | 부록만 |
| `conflicting` | 서로 어긋남 | 부록만(양쪽을 함께 적음) |
| `needs_product_check` | 제품 확인 필요 | 부록만 |
| `stale` | 이전 버전 근거 | 부록만 |
| `unfit` | 맞지 않는 출처 | 부록만 |

### 1.4 버킷과 중단 유형 풀이

모든 URL은 네 버킷 가운데 하나로 끝납니다(`references/research/public-page-access.md` 6절).

| 버킷 | 풀이 |
| --- | --- |
| `read` | 읽음 |
| `deferred` | 보류(실행 안에서 다시 시도) |
| `unread` | 허용된 단계로 읽지 못함. 시도하지 않은 단계를 함께 적음 |
| `stopped` | 중단. 중단 유형과 함께 수집 공백이 됨 |

중단 유형은 다음 열한 가지입니다(`uxresearch/verdict.py`의 `STOP_CLASSES`와 같음).

| 코드 | 풀이 |
| --- | --- |
| `terms_restricted` | 약관 제한. 약관이 자동 수집을 제한한 호스트라 요청하지 않음 |
| `opted_out` | 거부 신호. robots.txt(다른 AI 에이전트 토큰 그룹 포함), noai, TDM 예약, 브리프의 제외 호스트 |
| `auth_gate` | 로그인, 회원, 본인인증이 필요함 |
| `paywall` | 유료 |
| `human_check` | 사람 확인(캡차 등) |
| `rate_limit` | 속도 제한 |
| `geo_block` | 지역 제한 |
| `legal_block` | 법적 차단(임시조치, 게시 중단 등) |
| `gone` | 삭제되었거나 없음 |
| `budget` | 예산 소진 |
| `host_stopped` | 호스트 중단(앞선 중단으로 이번 실행에서 닫힘) |

범위 밖은 수집 공백과 따로 셉니다. 비공개 채널(오픈채팅, 밴드, 페이스북 그룹 등)은 요청 전에 멈추고
`out_of_scope`로 셉니다. 검색 결과 페이지와 꺼 둔 발견 경로는 직접 넘기면 거절(exit 2, 버킷 `refused`)하고,
리디렉션 중에 만나면 범위 밖 중단으로 적습니다. 공식 경로의 키가 없는 경우(이유 코드
`official_route_needs_key:<환경 변수>`)는 수집 공백이자 사용자에게 묻는 질문입니다. `close`가 출력하는 요약의
`totals.terms_restricted`, `totals.stopped`, `totals.out_of_scope`, `totals.refused`와 호스트별 `stopped`로 아래 표를
채웁니다.

### 1.5 날짜와 시각

- 날짜는 ISO 형식(YYYY-MM-DD)으로 씀. 표, 근거 줄, 본문 모두 같음. "9월 29일", "2026.9.29" 같은 형식을 섞지
  않음.
- 시각은 "KST YYYY-MM-DD HH:mm"으로 씀.
- 기간은 "YYYY-MM-DD ~ YYYY-MM-DD"로 씀.
- 근거마다 게시일(`published_at`), 읽은 날(`observed_at`), 유효 시점(`valid_at`)을 따로 적음
  (`references/research/source-grading.md` 10절). 게시일을 모르면 "모름"이라고 씀.
- 유튜브 Data API로 받은 항목은 보관 기한(`retention_until`)을 적고, 그날이 지나면 지움.

| audience | 사용자 집단 | 타깃, 고객층 |

### 1.7 인용과 귀속

- 작성자의 이름, 닉네임, 프로필 링크를 쓰지 않음. 사람은 "작성자"나 "한 사용자"로만 가리킴.
- 작성자의 말은 본문에서 이렇게 적음: 작성자는 "…"라고 적었습니다 (작성자 진술, 사실 여부 미확인). 풀어 쓸 때도
  같은 꼬리를 붙임: 작성자는 결제 단계에서 본인인증 창이 두 번 떴다고 적었습니다 (작성자 진술, 사실 여부 미확인).
- 익명 1인칭 사연은 `narrative_unverified` 주의 표시와 함께 작성자 진술로 적고, 존재 근거로만 씀
  (`references/research/korea/platform-map.md` 4절).
- 풀어 쓰기를 먼저 씀. 원문 인용은 분석을 돕는 짧은 조각만 쓰고, 300자 이하, 출처당 5개 이하로 함. 풀어 쓴 문장을
  인용처럼 따옴표로 감싸지 않음.
- 팀 밖으로 나가는 보고서는 커뮤니티 출처를 채널, 날짜, 출처 ID로 밝힘(예: `kr-communities, 2026-08-14,
  SRC-1a2b3c4d`). 게시글 URL은 번들의 `source_ref`에만 둠.
- 사람이나 업체에 관한 주장(불친절, 사기, 조작 등)은 중립적으로 풀어 쓰고 단정하지 않음
  (`references/research/korea/legal-checklist.md` L18).
- 협찬 표지로 사람을 판정하지 않음. "홍보 신호"와 표지의 위치로 적고, 작성자를 광고주로 부르지 않음
  (`references/research/korea/promotion.md`, `references/research/korea/legal-checklist.md` L19).
- 커뮤니티의 성별·연령·정치 성향 추정치를 작성자, 주장, 페르소나에 붙이지 않음
  (`references/research/korea/platform-map.md` 4절).
- 인용문 속 `[phone]`, `[email]`, `[id-number]`, `[card]`, `[account]`, `[ip]`, `([ip])`, `[handle]`,
  `[profile-url]` 같은 자리표시는 reader가 식별 정보를 지운 흔적임. 되살리거나 고치지 않음. 계획된 `merge`의 원문
  대조도 지운 뒤의 글과 비교함.
- 건강, 장애, 나이 정보는 세그먼트 수준 주장에만 씀. 그런 주제의 커뮤니티 글은 풀어 쓰기만 씀
  (`references/research/workflow.md`의 Non-negotiable operating rules).
- 사용자가 승인한 커뮤니티의 회원 전용 글은 작성한 요약으로만 넣고, 발췌와 URL을 넣지 않음.
- 유튜브 Data API로 받은 댓글은 풀어 써서 넣음. 작성자 키에 보호 속성 단서를 붙이지 않음
  (`references/research/korea/legal-checklist.md` L17).

### 1.8 수치

- 수치마다 n, 모집단, 기준 시점, 출처를 붙임. 통계는 출처 카드와 함께 씀
  (`references/research/korea/statistics.md`).
- 게시글, 리뷰, 좋아요 수는 비율이 아님. "읽은 글 n건 가운데 m건"처럼 적고 비율로 바꾸지 않음
  (`references/research/source-grading.md` 6절).
- 측정 출처가 없으면 "많은 사용자", "대부분", "흔히", "다수"를 쓰지 않음.
- 나이 틀이 다른 수치를 더하거나 비교하지 않음(`references/research/korea/statistics.md` 3절).
- 별점 평균은 만족도 근거가 아님(`references/research/korea/promotion.md` 4d).

### 1.9 번역투 점검(탐지만)

보고서를 내기 전에 본문 문장에서 번역투를 찾습니다. 점검은 위치와 표현만 알려 주고 문장을 고치지 않습니다. 고칠지는
사람이 정합니다.

- 찾는 표현(이 스킬이 정한 목록): ~에 의해(서), ~를 가지다·~를 가지고 있다, 앞 문장을 받는 "그것은", 필요 없는
  "~것이다"·"~라는 것이다", ~에 대해(서)·~에 대한, ~를 통해(서), ~에 있어(서), ~되어지다·~되어진(이중 피동),
  출처를 뜻하지 않는 ~로부터, ~하는 것이 가능하다, 필요로 하다, ~중에 있다.
- 점검 대상에서 빼고 절대 고치지 않는 것: 인용문과 발췌, 출처 ID와 주장 ID, 숫자와 단위, URL, 상태 표시와 상태
  코드, 코드 이름, 법령과 약관 원문 인용, 자리표시(1.7절).
- 사람이 점검 결과를 보고 본문을 고친 뒤, 본문 문장(표, 인용, 코드 블록 제외) 가운데 바뀐 문장이 30%를 넘으면
  다른 사람이 다시 검토함. 뜻, 주장 ID 연결, 확신 표현이 바뀌지 않았는지 봄.
- 탐지만 하는 점검과 30% 변경 비율 검토 기준은 K-skill(NomaDamas/k-skill, MIT)의 korean-humanizer 문서에서 얻은
  생각임. 그 문서는 변경률 기준을 im-not-ai(epoko77-ai/im-not-ai, MIT) 프로젝트에서 가져왔다고 밝힘. 글, 목록,
  코드는 옮기지 않았고, 위 표현 목록과 검토 절차는 이 스킬이 정함. 이 출처 표시는 `THIRD_PARTY_NOTICES.md`의 K-skill
  항목과 같아야 함. [R01] [R02]

### 1.10 법령과 약관 표현

- "합법", "적법", "법적으로 문제없음"이라고 쓰지 않음.
- 법령은 조항과 판(법령 번호, 공포일이나 시행일)을 함께 적고, law.go.kr에서 대조하지 못한 것은 미확인으로 적음
  (`references/research/korea/legal-checklist.md`).
- 적용이 다투어질 수 있는 항목은 부록의 "법률가 판단 항목"에 둠.
- 보고서 머리에 "법률 자문 아님"을 적음.

## 3. 완료 기준(Done when)

- 보고서가 2절 뼈대의 제목을 모두 가짐. 빈 항목은 "없음"이나 "모름"임.
- 지원되지 않은 주장 ID가 부록 밖에 없음. `report-check`(계획)가 통과함. 나오기 전에는 손으로 확인하고 그렇게
  적음.
- 수집 공백 표에 열한 가지 중단 유형이 모두 있음(0건 포함). `terms_restricted` 줄이 빠지지 않음.
- 범위 밖 채널과 거절된 URL은 수집 공백과 따로 셈.
- 모든 수치에 n, 모집단, 기준 시점, 출처가 있음.
- 작성자의 이름, 닉네임, 게시글 URL이 없음. 인용은 300자 이하, 출처당 5개 이하임.
- 날짜는 ISO 형식, 시각은 KST YYYY-MM-DD HH:mm임.
- 번역투 점검을 돌렸고, 고친 문장이 30%를 넘었으면 다른 사람이 검토했음.
- 법령 언급마다 조항과 판, 확인 표시가 있고, 머리에 "법률 자문 아님"이 있음.

## 4. 실패 유형(Failure modes)

- 지원되지 않은 주장이 본문에 들어감: 부록으로 옮김.
- 게시글 수를 비율로 씀, 또는 "대부분의 사용자"처럼 분모 없는 표현을 씀: "읽은 글 n건 가운데 m건"으로 고침.
- 작성자를 닉네임으로 부르거나 광고주로 단정함: "작성자", "홍보 신호"로 고침.
- 번역투 점검이 인용문, 숫자, ID, URL을 고침: 점검 결과를 되돌리고 대상에서 뺌.
- 자리표시(`[phone]` 등)를 원래 값으로 되살림: 지운 상태로 되돌림.
- 수집 공백 표에서 약관 제한을 빠뜨림: 접근 표와 `close` 요약의 `totals.terms_restricted`로 채움.
- 범위 밖 채널을 수집 공백으로 셈: 범위 밖 표로 옮김.
- 날짜 형식이 섞임(2026.9.29, 9월 29일, 2026-09-29): ISO로 맞춤.
- 풀어 쓴 문장을 따옴표로 감싸 인용처럼 보이게 함: 따옴표를 뺌.
- 공개 웹에서 덜 잡힌 사용자 집단을 "없음"으로 읽음: 수집 한계에 적고 설문, 인터뷰, 팀 자료로 계획함.
